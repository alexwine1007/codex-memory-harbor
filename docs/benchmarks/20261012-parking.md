# 0.4.5-beta.2：安全停泊流水线对照

日期：2026-10-12。旧版：`32e85aef4f45cfa2a908574eb4c2e29ba0a9643c`；新版：本次工作树。设备：当前 Mac 内盘 → 已挂载 exFAT 外置 U 盘。只创建临时随机合成文件，不迁移用户素材或历史。

两轮分别执行旧版、新版；每轮结束独立核对原路径、外部目标的 SHA-256，再恢复本机普通文件并复核。所有临时文件已清理。

| 合成场景 | 第一轮旧 → 新 | 第二轮旧 → 新 | 第二轮提速 |
| --- | --- | --- | --- |
| 32 × 128 KiB，释放本地 | 25.762 → 0.608 s | 25.064 → 0.603 s | 41.58 倍 |
| 2 × 64 MiB，释放本地 | 2.109 → 1.392 s | 2.264 → 1.573 s | 1.44 倍 |
| 32 × 128 KiB，保留副本 | 23.828 → 0.576 s | 24.737 → 0.586 s | 42.23 倍 |

第二轮大文件安全流水线吞吐由 56.55 → 81.39 MiB/s。这里的分母包括复制、持久化、回读、链接、独立复核与释放，不是只测复制写入。

32 个小文件的系统句柄检查启动次数从 96 降为 3；每个来源仍参与三次新鲜检查，释放检查增加外部目标。原生 UUID 每次重新读取、不缓存；系统身份查询从逐文件的 128 次命令调用，改为 66 次新鲜卷属性查询。两版逐文件 SHA-256 回读均为 160 次；释放路径 fsync 均为 192 次，保留副本路径均为 128 次。第二轮计数不包括测试结束后的独立审计与恢复。

优化的是小文件固定开销，不是减少完整性工作。分组上限 32 个 / 4 MiB；大文件独立分组、串行写入，不用固定多写入并发抢占前台 I/O。

## 复现

```sh
python3 scripts/benchmark_parking.py --volume /Volumes/YOUR_DRIVE
MEMORY_HARBOR_TEST_VOLUME=/Volumes/YOUR_DRIVE python3 -m unittest discover -s tests -v
```

基准生成总计 136 MiB 随机来源，每一场景单独创建并清理。默认固定对照提交；只执行本仓库已信任的旧代码。原生 UUID 先与独立 `diskutil` 读回对照。

## 不能从本报告推出

- 缓存状态没有强制冷却，顺序固定旧 → 新；这些数值不是绕过缓存的介质持续上限。
- 未测得 `C_path`，因此 `η_copy / η_verified` 均未标定，不能声称已达产品 85% / 90% 目标。
- 不是数 GB 单文件、数千文件真实项目批次的完成时间预测。
- 没有测前台 Codex 交互 p95、热降速、拔盘重挂载、重启续接或掉电耐久。
- 第二个 Agent / Harness 适配器仍未交付。共享字节事务不是所有 Runtime 原生连续性已验收。
