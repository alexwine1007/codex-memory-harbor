# First-cohort plan / 首批内测两周计划

## Goal — not existing results

Recruit **5–10 willing testers** who have the actual problem. Suggested targets: 10 try a scan, 5 complete a disposable docking/restore trial, 3 voluntarily return after a week. These are goals, not claimed users. Stars, views and unique clones are not usage counts; clones can include bots and CI.

## Channels, in order

1. **GitHub home:** README, bilingual trial guide, short demonstration, source release assets and privacy-safe issue template. Finish this before sending anyone here.
2. **People already interested:** only with consent, invite a few relevant Mac/Codex users. No contact harvesting or unsolicited bulk messages.
3. **One Chinese developer community:** choose a relevant V2EX creation node or a substantive 掘金 technical article after checking current rules and owner/account approval. Explain the byte verification and recovery, not just an ad.
4. **Show HN:** after independent first-use feedback and known installation issues are documented. Link runnable code/trial, be available for questions, do not request votes. Avoid relaunching every small version.
5. **Helpful issue discussion:** only if the thread welcomes external workarounds and our OS/runtime matches. Never substitute link-dropping for a diagnosis.

No paid ads, fake accounts, new signup service, automated outreach or tracking pixels. No need to build a separate website yet; use one repository URL.

## Days 0–2

- [x] Cover/video/docs reviewed; only disposable fixture content visible.
- [x] Disposable trial and recovery tests pass; source beta limitations prominent. See [local verification](../verification/2026-10-13-launch.md).
- [ ] Upload social-preview cover in authenticated repo settings; adding the image file alone is insufficient.
- [ ] Owner approves a particular channel and exact post, then publishes once.
- [ ] Ask 2–3 consenting testers to try the guide without a live walkthrough. Record where they stop.

## Days 3–7

- [ ] Expand to 5–10 willing testers, fixing the biggest confusion first.
- [ ] Label feedback by outcome: scan / trial / restore / restart / remount. No aggregated “works” claim.
- [ ] Review actual safety issues before optimizing conversion. Stop encouraging real migrations if recovery fails.
- [ ] Reply helpfully to questions; do not solicit stars as payment for help.

## Days 8–14

- [ ] Optional one-week follow-up only with participants' consent. No recurring reminder without explicit authorization.
- [ ] Report counts based on voluntarily submitted evidence, not telemetry. State missing/unknown outcomes.
- [ ] Publish a short evidence-bounded changelog after tests; disclose source installation limitations.
- [ ] Decide whether install friction merits a signed/notarized binary project. Apple account, payment and terms require separate approval.

## Feedback fields / 记录维度

Version; macOS; drive class (USB flash / HDD / SSD); filesystem; which stage was completed; first confusing step; whether local copies were kept; whether restore was independently checked; optional week-later use; privacy-safe error class. Do not collect names, email, private history, full source paths or drive UUIDs.

## Owner decisions still required

Specific external platform/account and final post; recipient list for invitations; any expenditure; any personal disclosure; a public prebuilt app signing/notarization route. Draft completion and repository publication are not community-post completion.
