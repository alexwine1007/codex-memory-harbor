# Memory Harbor — first users, not vanity metrics

[简体中文](README.zh-CN.md) · [Safe first trial](TRY.md) · [Ready-to-edit posts](POSTS.md) · [Two-week checklist](PLAN.md)

**Codex histories filling your Mac? Extend local storage with an always-connected USB flash drive or external SSD/HDD, verify migrated old logs and cold media, and keep original paths readable for evidence review and later work.**

Real small-scale experiments cover Codex reads of external histories, including restart and safe remount for a one-task pilot. This does not establish that every old child agent can directly resume; keep the [read-versus-continuation distinction](../../README.md#can-codex-still-use-migrated-content).

Memory Harbor is a third-party, macOS-only source beta. It is not an official Codex integration, a whole-workspace mover, a second backup, or automatic memory for every conversation. Start with the read-only scan or disposable trial; keep local copies on a new machine/drive until you validate restart, remount and recovery.

## Start here

1. [Inspect without migrating anything](TRY.md#1-read-only-inventory).
2. [Try verified docking and restoration with one new sample](TRY.md#2-disposable-byte-transaction-trial).
3. [Report what worked or blocked you](https://github.com/alexwine1007/codex-memory-harbor/issues/new?template=beta_feedback.yml). On GitHub, choose **New issue → Beta trial feedback**. Do not share private logs or paths.

No email collection, sign-up, analytics SDK or new service. The single home is [the GitHub repository](https://github.com/alexwine1007/codex-memory-harbor).

## What is public and what is not

Repository documentation and reviewed demo assets can be published here. Community posts, issue replies and invitations below are **drafts, not sent messages**. Obtain the owner's channel-specific approval before posting; do not spam bug reports, solicit votes or pretend to be OpenAI. The first cohort target is 5–10 people with this actual problem, not a claimed user count.

The supplied social covers are separate from the app icon. Adding PNGs to the repository does **not** configure GitHub's social-preview setting: upload the English cover in **Settings → Social preview → Edit** when authenticated as the repository owner.

## Basis

The approach follows [Open Source Guides](https://opensource.guide/finding-users/): explain the problem, use one home and seek useful feedback from relevant communities. A [Show HN](https://news.ycombinator.com/showhn.html) submission should point to something people can actually try, not just a sign-up page; avoid asking for votes. [GitHub's cover guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/customizing-your-repositorys-social-media-preview) recommends 1280×640 and under 1 MB.
