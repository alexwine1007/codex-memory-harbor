# 项目文件与历史的透明停泊

- 状态：0.4.5-beta.2，本机 beta；历史与项目文件共用停泊引擎
- 更新日期：2026-10-12

## 使用方式

在“打开港口”后选择外置盘。在原列表内切换“任务历史 / 项目文件”；项目文件选择已保存项目，点击“查看可停泊文件”，再按目录或逐文件选择。两种内容共用底部“停泊所选”和原有确认、进度窗口，没有额外的项目方案弹窗。切换不会清除已选择内容，确认时明确显示历史数、文件数、总量和目标盘。查看方案和取消确认都不会迁移文件。

文件列表每页 100 项。按目录选择和全选覆盖完整候选清单，不只当前页；“下载文件清单”可保存全部来源、相对路径、字节数和冻结元数据。打开方案不会迁移文件。

第一次默认勾选“同时保留本地副本”。素材已放到外盘并建立原路径链接，但对应实体仍在 `.harbor-archive-rollback`，因此没有释放这部分空间。重新查看项目方案后，在“现有素材链接”选择具有当前回执的条目，使用“释放所选素材本地副本”或“恢复所选素材到本机”。本次明确取消保留副本时，也可以在独立复核后直接释放。

## 保留原入口的含义

本机项目根目录和子目录保留。符合条件的普通素材复制到 `Memory Harbor/Project Assets/<项目 id>/<原相对路径>`；原文件位置变成绝对符号链接。Codex、制作记录和相对素材引用继续使用原项目路径，不重新关联项目。恢复后原路径再次成为普通文件，外部副本保留。

这是项目文件的分层存储。说明文档、脚本、版本库、运行环境、凭据相关路径、未静置 30 天的文件、硬链接、特殊文件、资源分支和既有链接不进入候选。当前候选类型是图片、视频、音频、字幕、PSD 和 PDF。目录重名/大小写兼容及任意文件格式还需专门验收，不保证完整工作区移植。

## 冻结方案与事务

服务保存来源的相对路径、长度、inode、设备号、mtime、ctime及所选卷的 UUID，方案有效期一小时。提交只接受该服务器方案中的来源；更换目标、加入其他路径、来源发生变化或项目刚被设为本机保留都会停止。页面操作串行；逐文件锁以原来源路径为键，阻止不同服务进程同时处理同一素材。

每个文件依次经过：

1. 卷身份和来源状态检查，有界 `lsof` 检查打开句柄。
2. 独占创建目标，流式复制、源 SHA-256、文件 fsync 和目标父目录 fsync。
3. 目标回读、长度与哈希复核，再检查来源没有变化或被打开。
4. 暂存本地回滚副本，建立原位置链接，同步本机目录。
5. 分别回读外部实体、原路径链接和本地副本，持久化 UUID/路径/长度/哈希回执。
6. 用户选择释放时再核对外部和本地副本，释放对应实体并同步目录。

第一项失败即停止批次，已经完成的条目保留完成状态；没有覆盖目标、自动删坏副本或重新展开文件列表。错误可能留下外盘不完整目标，需要取证后处理，不能盲目重试覆盖。

历史、项目文件与显式文件清单使用同一个 `archive_batch` 复制/校验/替换核心；历史的候选保护、JSONL 语义、旧清单和恢复入口不改。小文件按最多 32 个、合计最多 4 MiB 的有界阶段分组，每个来源仍参与复制前、替换前、释放前三次新鲜句柄检查；释放前同时检查外部目标与本地副本。不缓存“文件空闲”或“外盘在线”结论。大文件独立成组，不同时启动多个磁盘写入事务。

macOS 每次卷身份门均重新查询持久 UUID；原生卷属性不可用时退回最长 3 秒的 `diskutil` 查询，无法确认即停。逐文件 SHA-256、目标回读、链接/本地副本独立复核、释放前回读、文件与目录 fsync、回执持久化均保留。改动节省的是系统命令启动成本，不是删校验。完成后原进度窗口展示安全流水线耗时，阶段详情折叠；未测物理上限时不展示伪造效率百分比。

批次提交获得一次性方案与进度 id，同一方案重复提交返回原批次，不重复迁移。进度查询只在操作期间运行。服务重启不会自动重放迁移；当前进度是内存状态，持久回执与回滚副本是恢复依据。不可把它当成掉电恢复协议。

## 边界和恢复

- 卷在线时原路径可读；卷离线时原始素材不可读，本机目录和工作文件仍存在。
- 默认本机副本用于回滚，不是自动离线读取缓存。离线编辑和自动热缓存尚未交付。
- 文件内容允许按原路径读取；停泊期间不要编辑素材。停泊后改写外部实体会使旧回执失效，停止释放与恢复，不静默覆盖新内容。
- 本流程保证字节副本与出处，不保证可执行权限、ACL、Finder 标签等全部平台文件语义。含资源分支的素材排除在候选之外。
- 任一替换前失败保留原件；替换后验证或回执失败回退本机原件。成功停泊后，恢复校验失败保留外部实体和本地回滚副本。
- 旧维护工具生成的外部链接继续保留；没有新版方案与匹配回执时，页面不擅自接管它们。
- 项目素材链接的自动卷改名修复尚未交付；历史记录的 `repair-links` 不能代替素材链接修复。首次批次保持既有挂载名称，换盘和改名另行验收。
- 本版本没有放开 Codex 主任务保护；也不把项目文件副本等同于新增 Runtime Adapter。
- 单元测试和样例回环服务不能替代真实项目批次、Codex 重启、睡眠、实际拔盘重挂载和突然掉电验收。首次素材批次由用户操作后分别记录这些证据。

维护命令仍兼容仓库的 `scripts/archive_verified_files.py`；实现随 Skill 安装在 `scripts/archive_files.py`。项目 JSON 清单保留目录层级，不把同名文件压成单一目标。`--execute` 明确执行；项目清单默认保留副本，`--release-local` 才请求释放，`--restore --execute` 按原清单恢复。
